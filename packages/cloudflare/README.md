# @effectivity/cloudflare

The Workers runtime package: R2 bytes, D1 identity, the composed worker
that runs the whole CMS, and the Cloudflare platform plugin that owns all
orchestration behind the generic `@effectivity/cli` engine.

- `effectivity.config.ts` — the source of truth for the instance: catalog
  root, auth origin/secret, admin email, and the Cloudflare targets. It
  registers the package's own `cloudflarePlugin(...)` factory.
- `wrangler.jsonc` + `src/runtime.generated.ts` — generated by
  `effectivity sync` (`bun run cms sync`): bindings-only wrangler config,
  and the settings object baked into the worker bundle. Runtime settings are
  NOT environment variables.
- `src/plugin.ts` — `cloudflarePlugin(config)`: a capability registration
  (`sync`/`dev`/`build`/`preview`/`seed`) over the Vite dev engine. All
  Cloudflare orchestration lives here, never in the CLI. The registration
  name is `config.name` (default `effectivity-cms`), so it also names the
  plugin's command group.
- `src/r2-blob-store.ts` — the @effectivity/core `BlobStore` seam over an R2
  binding (etag token = the raw unquoted R2 etag, which the conditional API
  accepts; infra failures map to the seam's declared errors).
- `src/composition.ts` — `createComposition(env)`: migrations + admin seed at
  first boot, `/auth/*` dispatched to the Better Auth handler, everything
  else through `HttpRouter.toWebHandler(App.routes(...))`.
- `src/index.ts` — the Worker object (module-level memoization per isolate).

## Configure

The instance is configured in `effectivity.config.ts` — the engine's
Vite-style `defineConfig`, listing the Cloudflare plugin factory call:

```ts
import { defineConfig } from "@effectivity/cli"
import { cloudflarePlugin } from "@effectivity/cloudflare"

export default defineConfig({
  plugins: [
    cloudflarePlugin({
      name: "effectivity-cms",
      r2: { bucket: "effectivity-cms" },
      d1: { name: "effectivity-auth" }, // id: optional; placeholder until provisioned
      auth: {
        url: "http://localhost:8787",
        admin: {
          email: "admin@effectivity.local",
          password: "admin-seed-password-0123", // dev only: .dev.vars
        },
        // secret: "<64-hex>",   // dev default is baked into runtime.generated.ts
      },
      catalog: { root: "cms" },
    }),
  ],
})
```

Everything non-secret (root, origin, signing secret dev default, admin
email) is baked into `src/runtime.generated.ts`. The admin password is never
baked: `dev` writes it to `.dev.vars`, and production overlays it at deploy
time. Production may overlay any baked value by setting
`AUTH_URL`/`AUTH_SECRET`/`AUTH_ADMIN_EMAIL`/`AUTH_ADMIN_PASSWORD` in a
wrangler environment (a `wrangler secret put` wins at runtime). The only
required bindings are `BUCKET` (R2) and `DB` (D1).

## Runbook (via `@effectivity/cli`)

```sh
cd packages/cloudflare
bun install
bun run cms --help        # command overview (no config needed)
```

### Develop

```sh
bun run cms dev [--port 8788]   # sync, write .dev.vars secrets, vite dev (workerd HMR)
bun run cms seed [--url URL]    # seed example content at a running worker
bun run cms build               # sync + vite build (worker bundle to dist/)
bun run cms preview             # vite preview (serves the built bundle)
bun run cms sync                # regenerate wrangler.jsonc + src/runtime.generated.ts
bun run cms init [dir]          # write a starter effectivity.config.ts in a new project
```

`dev` runs the Worker in workerd via the Cloudflare Vite plugin (HMR, port
honored), with bindings and compat settings read from the generated
`wrangler.jsonc`. `build` produces the bundle to `dist/`; `preview` serves
it. The Vite engine is configured in the committed, hand-owned
`vite.config.ts` (`plugins: [cloudflare()]`).

`dev` and `preview` do not return while the server runs. A registered plugin
placed after the Cloudflare plugin does not run for those two capabilities.
This is the engine's documented long-running-operation limitation.

### Regenerate manufactured files

```sh
bun run cms sync            # regenerate wrangler.jsonc + src/runtime.generated.ts
bun x wrangler types        # regenerate worker-configuration.d.ts; commit it
```

## Behavior

- First request per isolate runs the migrations (`getMigrations` runs
  better-auth's schema diff against D1) and seeds the admin from the baked
  `auth.admin.email` plus `AUTH_ADMIN_PASSWORD` when no such user exists.
- Reads are public; writes authenticate via session cookie or `x-api-key`,
  with `If-Match` conditional semantics; `/openapi.json` is served.

## HTTP API

Base URL: `http://localhost:8788` in dev, or the deployed URL. Reads are
public; writes require a session cookie from `/auth/sign-in/email` or an
`x-api-key` header. Conditional writes: create without `If-Match` (201),
update with it (200); a stale or unknown `If-Match` returns 412. Every write
honors this uniformly for documents and assets.

Asset urls resolve to the API's own origin (`GET /assets/{id}`), so embedded
images can be linked directly from rendered documents — `/references` and
`?view=model` both carry the absolute `url` per reference. `PUT /assets/{id}`
accepted content types: `application/octet-stream`, `text/plain`, `image/png`,
`image/jpeg`, `image/gif`, `image/webp`, `image/svg+xml`, `application/pdf`;
anything else is a 415. The uploaded content type is retained and served back
on reads, so browser links render instead of downloading.

| Method + path                  | Auth    | Behavior                                                                                                                                                                                                                                                          |
| ------------------------------ | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /openapi.json`            | —       | OpenAPI 3 document                                                                                                                                                                                                                                                |
| `GET /documents`               | —       | catalog listing (`?folder=guides` filters)                                                                                                                                                                                                                        |
| `GET /documents/{path}`        | —       | raw markdown; `?view=model` = parsed model + `references[]` with absolute urls; `?resolve=urls` rewrites image srcs and doc-to-doc links in place (catalog paths, `./`/`../`, `docs/` and `/`-prefixed, `assets/…`; externals untouched); `etag` header = version |
| `PUT /documents/{path}`        | ✓       | create (201) / conditional update (200/412)                                                                                                                                                                                                                       |
| `DELETE /documents/{path}`     | ✓       | idempotent 204; integrity refusals 409                                                                                                                                                                                                                            |
| `GET /assets`                  | —       | asset listing                                                                                                                                                                                                                                                     |
| `GET /assets/{id}`             | —       | raw bytes served with the content type it was uploaded with; `etag` header = version                                                                                                                                                                              |
| `PUT /assets/{id}`             | ✓       | create (201) / conditional update (200/412); content type retained from the request                                                                                                                                                                               |
| `DELETE /assets/{id}`          | ✓       | idempotent 204; integrity refusals 409                                                                                                                                                                                                                            |
| `GET /references`              | —       | per-document reference report: author `src`, resolved asset id, absolute `url`, status                                                                                                                                                                            |
| `POST /auth/sign-in/email`     | —       | email/password, sets a session cookie                                                                                                                                                                                                                             |
| `POST /auth/sign-out`          | ✓       | ends the session                                                                                                                                                                                                                                                  |
| `POST /auth/api-key/create`    | ✓       | issues an API key (shown once)                                                                                                                                                                                                                                    |
| `POST /auth/admin/create-user` | ✓ admin | provisions an account (`{email,password,name}`)                                                                                                                                                                                                                   |

### Example curls (local dev)

The admin sign-in uses the `.dev.vars` credentials and must send an `origin`
header matching `AUTH_URL`:

```sh
# 1. discover the API
curl http://localhost:8788/openapi.json

# 2. sign in, keep the session cookie
curl -c /tmp/cj.txt -X POST -H "content-type: application/json" \
  -H "origin: http://localhost:8787" \
  --data '{"email":"admin@effectivity.local","password":"admin-seed-password-0123"}' \
  http://localhost:8788/auth/sign-in/email

# 3. create a document (201, version returned)
curl -b /tmp/cj.txt -X PUT -H "content-type: text/markdown" \
  -H "origin: http://localhost:8787" \
  --data $'---\ntitle: Hello\n---\n# Hello world' \
  http://localhost:8788/documents/hello

# 4. update conditionally: read the etag, send it back as if-match
curl -s -D - -o /dev/null http://localhost:8788/documents/hello   # note: etag:
curl -b /tmp/cj.txt -X PUT -H "content-type: text/markdown" \
  -H "origin: http://localhost:8787" -H "if-match: <etag-from-read>" \
  --data $'---\ntitle: Hello\n---\n# Hello v2' \
  http://localhost:8788/documents/hello          # 200

# 5. headless write with an API key (create a key first, step 8)
curl -X PUT -H "content-type: text/markdown" -H "x-api-key: <key>" \
  -H "origin: http://localhost:8787" \
  --data $'---\ntitle: Hi\n---\n# Headless' \
  http://localhost:8788/documents/headless       # 201

# 6. assets and the reference report
curl -b /tmp/cj.txt -X PUT -H "content-type: application/octet-stream" \
  -H "origin: http://localhost:8787" --data-binary 'logo bytes' \
  http://localhost:8788/assets/logo.txt          # 201
curl http://localhost:8788/references            # present / dangling

# 7. provisioning (admin only; the role gate returns 403 without it)
curl -b /tmp/cj.txt -X POST -H "content-type: application/json" \
  -H "origin: http://localhost:8787" \
  --data '{"email":"writer@example.local","password":"writer-password-0123","name":"Writer"}' \
  http://localhost:8788/auth/admin/create-user   # 200

# 8. API key for scripted clients (printed once)
curl -b /tmp/cj.txt -X POST -H "content-type: application/json" \
  -H "origin: http://localhost:8787" --data '{"name":"ci"}' \
  http://localhost:8788/auth/api-key/create

# 9. the identity store (local D1)
bun x wrangler d1 execute effectivity-auth --local \
  --command "SELECT email, role FROM user"
```

## Tests

`bun run test` — the Workers vitest pool (workerd) against the emulated
bindings: the R2 adapter mirroring the core blob oracle, the composed worker
end-to-end (dispatch, session/API-key-gated writes, migrations + seed at
boot, OpenAPI), and the Cloudflare plugin (fake `FileSystem` +
`ChildProcessSpawner` boundaries, no workerd involved).

## Notes

- Version tokens are R2 etags, so they differ from the memory seam's counter
  values seen in other packages; they round-trip through `If-Match` on the
  same store, which is the contract.
- In-process events (core) do not fan out across Worker instances; v1 assumes
  a single instance (documented core limitation).
